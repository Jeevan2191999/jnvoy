# Evaluation

How well Jnvoy hides sensitive values, measured in ways you can repeat. Everything here runs on your machine.
The numbers on https://www.jnvoy.com/accuracy come from these files.

| File | What it is |
|---|---|
| `large.jsonl` | 1,000 documents, 1,758 sensitive values. Values generated by Faker in formats from several countries, sentences written by us. The development set: rule fixes are made by looking at its misses. |
| `large_heldout.jsonl` | 600 more documents from a different seed. Used only to check totals while fixing rules. Same sentence wordings as `large.jsonl`, so a fix written for those wordings helps it too. |
| `large_fresh.jsonl` | 600 documents with a second wording for every kind of value (`generate_large.py --phrasing fresh`). Unseen after round one; its misses were read and round two was written against them, so it is spent. |
| `large_fresh2.jsonl` | 600 documents with a third wording (`--phrasing fresh2`), written before round two and never used to change a rule. This is the number to trust. Its misses were read to describe them on the page, so it is spent too: the next round needs a new one. |
| `refresh_results.py` | Re-measures every set (a few minutes) and rewrites `results_large.json`. |
| `generate_large.py` | Regenerates both sets from a fixed seed (needs `pip install faker`). |
| `compare.py` | Scores Jnvoy against plain Presidio on a labelled file, with 95% intervals and a paired significance test. |
| `breakdown.py` | Splits the misses by format (capital-letter names, "pwd" passwords, card lengths). |
| `check_my_data.py` | Scores Jnvoy on your own labelled text. This is the number that matters. |
| `results_large.json` | The stored output of the runs above, with library versions and file checksums. |
| `medical_terms_eval.py` | Measures the opt-in `MEDICAL_TERM` detection on 263 invented sentences: words on its list, words it was not given, medicines with a dose, everyday uses. Writes `medical_terms.jsonl` and `results_medical_terms.json`. |
| `injection_eval.py` | Measures prompt-injection blocking: 740 held-back and 665 development real jailbreak prompts and 52,002 ordinary prompts from public sets (fetched, not stored), plus 223 hand-written cases in `injection_cases.py`. Writes `results_injection.json` and `injection_handwritten.jsonl`. |
| `protected_terms_eval.py` | Measures the `protected_terms` setting on 272 invented client and project names, in forms it is built to find and forms it is not, plus names never listed. Writes `protected_terms.jsonl` and `results_protected_terms.json`. |
| `run_eval.py` and the other `*.jsonl` files | The older, small, hand-written sets. They are optimistic. |

## Run it

```bash
python evaluation/compare.py                                          # Jnvoy vs Presidio on large.jsonl
python evaluation/compare.py --dataset evaluation/large_heldout.jsonl # the unseen set
python evaluation/compare.py --small-model --no-presidio              # the model the hosted service runs
python evaluation/compare.py --misses --no-presidio                   # list every leaked value
python evaluation/check_my_data.py evaluation/example_my_data.csv     # the format for your own text
```

## What a result means

- A value counts as **hidden** only if neither the whole value nor any recognisable part of it (a surname, the last digits of a number) is still visible. This is strict on purpose.
- **Kept** is the share of harmless words (company names, places, ticket numbers) left readable.
- Every share has a 95% Wilson interval. With few values it is wide. Believe the interval.
- The Presidio runs use the same spaCy model as Jnvoy, with Presidio's own recognisers. They are not any particular product's configuration. `presidio_tuned` switches off dates, places and nationalities, which is what a careful team would do; it then cannot see a birth date at all because Presidio has no birth-date recogniser.

## What it does not show

- The text is synthetic. Real documents are messier, so expect real accuracy to be lower.
- It measures patterns and names. It does not measure whether confidential business text, source code or trade secrets would be caught, because Jnvoy does not look for those. The one exception is names a customer lists in `protected_terms`, which `protected_terms_eval.py` measures separately.
- Nobody outside the project has run it yet. If you do, tell us what you got, including when it is worse.

## Changing the rules

1. Look at misses on `large.jsonl` only (`compare.py --misses`).
2. Fix the rule and add a test for it, including a test that it does not fire on ordinary text.
3. Check totals on `large_heldout.jsonl` and on a set whose wording you have not used. Make a new one with another seed
   (`generate_large.py --seed 777 --docs 600 --phrasing fresh --out ...`) once `large_fresh.jsonl` has been read.
4. Re-measure and refresh the page: `python evaluation/refresh_results.py`, then
   `python scripts/render_independent_accuracy.py --write`. The causes written under "What it still misses" are
   text, not numbers: read the new misses and rewrite them by hand.
   `tests/test_larger_accuracy.py` fails until the page and the file agree, and (with the pinned spaCy) until the file and the code agree.
