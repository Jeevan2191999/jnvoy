Accuracy

How well Jnvoy hides personal data, measured on example text we wrote ourselves. The misses are listed, and so are the limits of the test.

The result

Read the larger test as well. It has 1,000 documents with generated values and gives a lower figure, about 77%, than the small hand-written sets below.

On a fresh set of examples written after our last round of fixes, with no rule changed after seeing its results, the hosted service, which on 28 October 2026 was running the small language model (check /health for the current one), hid 32 of 37 sensitive values (86.5%). With the large language model, which the tables below use, Jnvoy hid 34 of 37 sensitive values (91.9%) and left 20 of 21 harmless words (95.2%) readable. That is a good result for a first pass and it is not a guarantee: do not rely on any redaction tool as your only control.

A value counts as hidden only if neither the whole value nor any recognisable part of it (a surname, the last digits of a number) is still visible in the redacted text. These are first-pass results: the optional second check is off on the hosted service.

Which language model. The figures above use the large English model (en_core_web_lg). A server that has only the small model (en_core_web_sm) hides fewer names: on the fresh held-out set it hid 32 of 37 (86.5%) instead of 34. The hosted service reports which model it is running at /health, under detector.spacy_model.

Speed on these short texts (35 to 50 characters each) was 16 to 32 milliseconds each in a small cloud container. We have not measured longer texts or the hosted service under load.

A larger test: 1,000 documents with generated values

The sets above were written by the person who wrote the detector, so they flatter it. To see how much, we built a larger set where the values (names, emails, phone numbers, addresses, card numbers, bank numbers, dates of birth, IP addresses, keys and passwords) are generated by Faker, a public library, in formats from several countries. We still wrote the sentences around them, so this is not an independent evaluation, only a harder and larger one. It has 1,000 documents, 1,758 sensitive values and 900 harmless words that should stay readable, and it is made from a fixed seed so anyone can regenerate it.

Result. Jnvoy hid 1,352 of 1,758 sensitive values (76.9%; the likely range is 74.9 to 78.8). With the small language model that the hosted service runs it hid 77.4% (range 75.3 to 79.3). On a second set of 600 documents that nobody looked at while fixing rules, it hid 78.8% (range 76.3 to 81.1). This is lower than the 86% to 92% on the hand-written sets above, and it is the figure to trust more. Roughly one sensitive value in four was still visible afterwards.

Harmless words kept readable. Jnvoy kept 92.9% (91.0 to 94.4). Presidio with its default settings kept 43.6% (40.4 to 46.8), because it hides dates and places by default. With those switched off it kept 77.0% (74.1 to 79.6) and hid 61.3% of the sensitive values against Jnvoy's 76.9%; without a date type it cannot see a birth date at all.

Where Jnvoy is ahead, behind, or too close to call

  • Clearly ahead of Presidio's defaults (the ranges do not overlap): API_KEY (100.0% against 14.3%), PASSWORD (75.3% against 19.2%).
  • Clearly behind: POSTCODE (26.8% against 41.3%).
  • Too close to call at this sample size (the ranges overlap, so a difference in either direction could be chance): PERSON (71.7% against 76.1%), IBAN (97.0% against 97.0%), ADDRESS (38.5% against 30.7%), PHONE (90.6% against 93.9%), CARD (76.2% against 89.1%).

The comparison is with Presidio on its own, using the same language model, and is not any product's configuration. Overall, Jnvoy hid 76.9% against 70.4% for Presidio's defaults, and the difference is not chance (McNemar test, p below 0.001).

What it misses most, in the formats that cause it

  • Names written in capital letters: 8 of 72 (11.1%) hidden, against 223 of 227 (98.2%) for ordinary "First Last" names.
  • Names written "Surname, First": 30 of 65 (46.2%) hidden.
  • Passwords introduced by "pwd": 0 of 18 (0.0%) hidden, against 55 of 55 (100.0%) when the word "password" is used.
  • Card numbers of some lengths: hidden, by number of digits: 12-digit 0 of 7, 13-digit 8 of 8, 14-digit 11 of 11, 15-digit 12 of 15, 16-digit 46 of 53, 19-digit 0 of 7.
  • Street addresses in forms other than the common UK, US, French and German patterns, such as "895 Smith Corner", and postcodes outside the UK and US (for example five-digit German codes).

These are measured gaps, not fixed ones. When rules change, this section is measured again and replaced.

How to read it

  • The values are synthetic and were not chosen by us, but the sentences around them were. Real documents are messier, so expect real accuracy to differ, probably downwards.
  • A value counts as hidden only if neither the whole value nor any recognisable part of it is still visible. This is strict: a street name left behind a hidden house number counts as a leak.
  • The second set is kept unseen: rules are fixed by looking at misses on the first set only, and the second set is used to check that a fix helps on text it was not tuned on.
  • The best figure is the one you get on your own text. python evaluation/check_my_data.py your_file.csv measures it on your machine without sending anything anywhere.

What it gets wrong

Sensitive values it still misses

  • A single-word house name, such as "Oakwood, Bell Lane" or "Hillcrest, Station Road".
  • A named house written inside a sentence instead of at the start of an address line, such as "She moved to Rose Cottage near Whitby" or "The farm, Primrose Farm, is near Skipton".
  • Danish street names ending in "-gade", such as "Vestergade 4". Other Nordic street words have not been tested.
  • An uncommon name in a sentence-style list, such as "attendees were A, B and C", where one of the names is not recognised as a name. Names after a title, a greeting, a label such as "Name:" or a sign-off are now found by rules, but a name with no such cue in a short sentence can still be missed, most often with the small model.

Harmless text it hid by mistake

  • A Unix timestamp that looks like an NHS number.
  • The words "Downing Street", read as a street address.
  • Brand names that start with a title, such as "Dr Pepper" or "Dr Martens", read as a person's name.
  • A company named after people, such as "John Lewis", when it follows a verb such as "email" or "call".
  • The city name "Lisboa" after a street address, read as a person.
  • An invoice number that looks like a phone number.
  • A link to public documentation, hidden as a web address.

Hiding too much costs you a slightly worse prompt. Hiding too little is the serious error, and the missed values above are the ones to watch.

Limits of this test

  • Written by us. The sets above are synthetic text from the person who built the tool, and in the larger test only the values are generated by someone else. None of it is an independent evaluation. Nobody outside the project has measured Jnvoy yet.
  • Small, except the larger test. 37 sensitive values in the fresh held-out set is a gauge, not a statistical measurement. The larger test has 1,758, with ranges shown, but its text is still synthetic. Expect real figures to differ, probably downwards.
  • Mostly English, mostly short. Names are detected best in English, and street addresses best in UK, US, French, German, Dutch, Spanish, Italian and Portuguese formats. Other languages have had little testing.
  • Country identifiers were tested only on published sample numbers. Accuracy on real data in those countries has not been measured.
  • No real customer data was used. Every value is invented or a documented example number.
  • Library versions matter. These numbers were measured with Python 3.12, spaCy 3.7.5 and its en_core_web_lg 3.7.1 model, except where the small model is named. Newer versions scored one or two values differently in our checks.
  • It will change. The sets and the scores are kept in the repository, and a test fails if this page and the measured numbers disagree.

Repeat it yourself

The data and the script are in the evaluation folder. After installing the requirements, run python evaluation/run_eval.py --dataset evaluation/holdout5.jsonl --misses to see the table above and every value that leaked. If you find text it should have caught, open an issue with a made-up example of the same shape.

For the larger test: python evaluation/compare.py scores Jnvoy and Presidio on the 1,000 documents with 95% ranges, and python evaluation/compare.py --dataset evaluation/large_heldout.jsonl does the same on the second set. To measure Jnvoy on your own text, put it in a CSV with columns text, sensitive and keep (see evaluation/example_my_data.csv) and run python evaluation/check_my_data.py your_file.csv. Nothing leaves your machine.
